# Multi-source requirements research

Research date: 2026-07-31. Evidence URLs and short attributable excerpts are retained in this decision record. Source snippets are requirements signals, not statistically representative surveys.

## Source summary

| Source type | Concrete pain or request | Frequency signal |
|---|---|---:|
| Reddit communities | Startups prioritize a caching/logistics layer that cuts API fees and latency; teams need cost/latency outlier analysis; users value open-source, easy-to-deploy monitoring and prompt management. | 3 |

| G2 reviews | Advanced analytics are limited; GUI/documentation flexibility is missing; complexity, bugs, and insufficient docs hurt onboarding. | 3 |

| Stack Overflow | Developers struggle to enforce TPM and RPM atomically across workers; need token estimates before dispatch; ambiguous 429 errors blur quota exhaustion versus request-rate exhaustion. | 3 |
| Competitor changelogs/roadmaps | Per-member budgets and cost analytics; compliance routing and guardrails; organization-level analytics and model/key/member breakdowns. | 3 |
